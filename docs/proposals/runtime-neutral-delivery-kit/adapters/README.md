# Binding profiles

Both JSON profiles are PROPOSED capability requirements, not verified adapters.
No Multica runtime API was queried to certify capabilities. The exact source
operations guidance is bundled under ../reference/software-factory/.

The Multica reference retains exclusive start trigger, complete child skeleton,
attributable review and routing-only coordinator. Its instruction safeguards are
not evidence of atomic backend deduplication. A company adapter must demonstrate
equivalent behavior rather than copy vendor mentions or issue URLs.

Capability meanings:

- exact-inputs/1: admit only verified control/contracts/input digests and ancestry.
- durable-receipts/1: inspect complete identity/history after ambiguous dispatch.
- independent-review/1: authenticate different reviewer actor/run and exact candidate.
- isolated-workspace/1: prevent parallel/arm context and write interference.
- mutation-boundary/1: enforce governed claims and reject unknown overlap.
- reconcile-cancel/1: serialize cancellation/settlement and reconcile remote effects.

A declaration is checked against empirical evidence before status VALIDATED. Profiles
also need a verified skill-loading mechanism, permission policy and aggregate
resource enforcement; a matching capability string alone does not qualify.
