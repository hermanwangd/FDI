# Structural Intelligence → Feature Discovery Integration v0.2

**FDI release:** v0.4.7.1
**Scope:** T2 candidate augmentation only.

## Contract

Structural Intelligence produces non-authoritative repository hints. A hinted repository may enter T2 repository investigation only after exact repository identity is grounded in eligible **PA-03 CB-01 identity-only** state.

```text
StructuralDiscoveryHintSet
        ↓
PA-03 CB-01 identity-only grounding
        ↓
repository candidate augmentation
        ↓
current feature investigation
        ↓
current feature-specific Evidence
        ↓
CONFIRMED / EXCLUDED / UNRESOLVED
```

Candidate augmentation retains the existing legal basis:

```text
basis = LAYER2_PA03
```

Structural provenance is supplementary and must retain exact snapshot / observation provenance.

## Identity substrate is not semantic Product Intelligence

For F001 ablation integrity, all arms may share the same PA-03 CB-01 repository identity substrate when canonical CandidateRepoSet normalization requires PA-03 identity. That substrate is restricted to exact repository identity and exact eligible PA-03 reference material.

It **must not include capability terms**, Product Realization relations, Delivery Intelligence, semantic descriptions, inferred ownership, historical ranking, or any other semantic Product Intelligence signal.

Therefore the B Structural-only arm means:

```text
shared repository identity substrate: YES
semantic Product Intelligence: NO
live Structural Intelligence: YES
```

and not “no PA-03 bytes of any kind.”

## Current-truth boundary

Structural Intelligence does not define a new HERM-211 candidate basis and cannot directly establish `CONFIRMED`, `EXCLUDED`, `ChangeSurfaceSet`, or `SPEC_READY`.

Unknown, stale, superseded, out-of-scope, or otherwise ineligible repository identities remain diagnostics/incompleteness for bounded investigation rather than current Feature truth.
