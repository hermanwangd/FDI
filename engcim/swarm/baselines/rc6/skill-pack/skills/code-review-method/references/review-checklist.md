# Review 分類檢查清單

> 用法：審查時逐項過，每項標「通過／問題（寫位置）／不適用（理由）／未審查」。
> 複製本清單進判定報告附錄，不許只打總勾。

## 1. 正確性

- [ ] 任務描述／SPEC 目標逐項核對：已實現／未實現／部分實現（逐項列出）
- [ ] 邊界條件：空輸入、null/None、空集合
- [ ] 邊界條件：極大輸入、超長字串、數值溢出
- [ ] 並發：共享狀態是否有競態；鎖／事務範圍是否正確
- [ ] 重試路徑：重試是否安全（對齊冪等宣告）
- [ ] 錯誤否定條件、off-by-one、未釋放的資源（連線/檔案 handle/鎖）
- [ ] SPEC 不變式在程式碼中可對應（斷言/約束/測試）
- [ ] 可執行的驗證已執行；未執行的部分已在判定中標明

## 2. 契約合規

- [ ] 端點／事件／函式簽章與 SPEC 契約一致（逐個比對）
- [ ] 破壞性變更已升版本，且消費者已通知
- [ ] 輸入驗證：每個參數的範圍檢查與契約一致
- [ ] 錯誤碼：實作產生的失敗全部在錯誤碼表內；無表外失敗
- [ ] 錯誤回應體 schema 固定（code/message/retryable/details），無堆疊洩露
- [ ] 冪等策略被實作（冪等鍵去重／天然冪等／拒絕重複）
- [ ] 資料 schema、遷移策略與 SPEC 一致
- [ ] 敏感欄位：日誌脫敏、回應過濾到位

## 3. 測試覆蓋

- [ ] 每個新行為有對應測試（無測試的新行為 → REVISE）
- [ ] 錯誤路徑有測試（不只 happy path）
- [ ] 邊界條件有測試
- [ ] 契約變更有契約測試
- [ ] 測試斷言行為，不斷言實作細節
- [ ] 無被 skip／註解／永遠通過的測試
- [ ] 測試已實際執行且通過（附執行證據）

## 4. 可維護性

- [ ] 命名表意；半年後可定位
- [ ] 無重複邏輯（兩處以上 → WARNING 起跳）
- [ ] 無死碼／被註解的程式碼
- [ ] 無除錯殘留（print/console.log/debugger）
- [ ] TODO 均有 owner 與期限；無 owner 的 TODO → REVISE
- [ ] 無過度設計：每個抽象層都指向已知需求
- [ ] 與 repo 既有慣例一致（不一致者已在交付說明給理由）
- [ ] 依賴新增有理由（為何不重用既有）

## 5. 橫切（交付物相關時適用）

- [ ] 安全：無明文 secret；輸入消毒；權限檢查在正確的層（Critical/High → REVISE，細則見 security-review skill）
- [ ] 日誌：不洩密、關鍵操作有審計點
- [ ] 遷移：向前相容或有明確停機/倒回計畫
- [ ] pipeline 變更：走過 review gate；無 secret 印出

## 判定速查

| 情況 | 判定 |
|---|---|
| 聲稱完成但未實現 | REVISE（最重） |
| 新行為無測試／測試未跑 | REVISE |
| 契約偏差未升版本 | REVISE |
| 表外失敗／錯誤體洩堆疊 | REVISE |
| 明確邏輯錯誤／資料損壞風險 | REVISE |
| Critical/High 安審 finding | REVISE |
| 除錯殘留／無 owner TODO | REVISE |
| 重複邏輯／命名／輕度過度設計 | WARNING |
| 測試品質問題但行為已覆蓋 | WARNING |
| Medium/Low 安審 finding（已開單） | WARNING |
| 全無問題 | PASS |
